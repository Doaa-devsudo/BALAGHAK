# Person 3: UI (`app.py`, `pages_/`)

## Your job
Two Streamlit pages: the **user chat** where people submit بلاغات, and the **admin dashboard**
where the supervisor follows them up. The dashboard is what the audience will look at most.

- **Files you own:** `app.py`, `pages_/user_chat.py`, `pages_/admin_dashboard.py`
- **Branch:** `ui`
- **You depend on:** `agent.run_agent` (stub until Checkpoint 2), `storage` (real),
  `rag.get_guideline` (already real).
- **Good news:** the dashboard uses real data (the 90 reports) from minute one.

## Before you start
1. Setup in `docs/00_TEAM_WORKFLOW.md` → section 1.
2. `git checkout -b ui`
3. `streamlit run app.py` → you should see both pages in the sidebar.
4. Open `data/reports.json` and look at the fields:
   `id, text, department, neighborhood, street, facility, priority, status, created_at`
5. Streamlit reruns the whole script on every click. Anything that must survive goes in `st.session_state`.

## Part A: User chat (`pages_/user_chat.py`), ~45 min
The stub already works. Improve it:
1. Short description under the title: «اكتب مشكلتك وموقعها وسنحوّلها للجهة المختصة».
2. Pass **only previous messages** as history: call `run_agent(prompt, st.session_state.messages)`

5. Optional: if the reply contains `RPT-`, show `st.success` with the ticket number.

## Part B: Admin dashboard (`pages_/admin_dashboard.py`), ~2.5 hours
Load once at the top: `df = pd.DataFrame(load_reports())`. Build it in this order:

### B1. Sidebar filters
`st.sidebar.multiselect` for department (options from `storage.DEPARTMENTS`), neighborhood
(`sorted(df["neighborhood"].unique())`), status (`storage.STATUSES`), priority (`storage.PRIORITIES`).
Apply them: `df = df[df["department"].isin(selected)]`, etc. Empty selection = no filter.

### B2. Metric row
`c1, c2, c3, c4 = st.columns(4)` and `st.metric` in each:
- إجمالي البلاغات
- جديد
- قيد المعالجة
- **عاجلة غير مغلقة** (`priority == "عاجلة"` and `status != "مغلق"`), the most important one for an admin.

### B3. Charts
Two columns:
- بلاغات حسب الإدارة: `st.bar_chart(df["department"].value_counts())`
- بلاغات حسب الحي: `st.bar_chart(df["neighborhood"].value_counts())`

### B4. Repeated reports (the "smart" feature)
- Take open reports: `status != "مغلق"`.
- Group by `["neighborhood", "street", "department"]` and count.
- Keep groups with count ≥ 2, sort descending.
- Show each as `st.warning(f"⚠️ {street} – {neighborhood}: {count} بلاغات مفتوحة ({department})")`.

The generated data has 3 such groups on purpose (حطين, الملقا, النرجس), so you'll see them.

### B5. Reports table
`st.dataframe` of the filtered data, newest first (`sort_values("created_at", ascending=False)`),
with nice Arabic column names (`df.rename(columns={...})`). `use_container_width=True`, `hide_index=True`.

### B6. Report detail + action
- `report_id = st.selectbox("اختر بلاغ", df["id"])`
- Show its text, location, facility (if any), priority, status, date.
- **Suggested action (RAG):** `rag.get_guideline(report["department"])`, then show only the part
  starting from «## الإجراء المقترح للمشرف» until the next «## », inside `st.expander("الإجراء المقترح")`.
  (Use `.split("## الإجراء المقترح للمشرف")[1].split("## ")[0]`.)
- Status change: `st.selectbox` with `storage.STATUSES` + a «تحديث الحالة» button →
  `update_status(report_id, new_status)` → `st.success(...)` → `st.rerun()`.
